# Projector 0.2.0

Release Date: 2026-10-02

## What's Changed

### Shared output-format handling (`src/format.rs`)

- All `-f, --format` values are now validated through one `OutputFormat` type.
  Previously nine subcommands each hand-wrote `if format != "json" { bail!(...) }`,
  and `stats`/`trend` silently ignored an unknown `-f` value and fell back to the
  terminal table. Every subcommand now rejects unknown formats with
  `Unsupported format: 'x'. Use 'terminal' or 'json' (or 'md' for report).`
  `report` keeps accepting `json` and `md`.

### Dependency version conflicts

- `projector deps --shared` now collects every distinct version requirement for
  a shared dependency. Projects pinning different versions (e.g. `serde 1.0` in
  one project and `serde ^2.0` in another) are flagged with
  `⚠ conflicting requirements`. The JSON report adds a `conflict` flag, the full
  `versions` list, and a `conflicts_count` summary.
- Shared detection now groups by dependency name **and** ecosystem, and requires
  two distinct projects (a dep listed in both `dependencies` and
  `dev-dependencies` of one project no longer counts as "shared").

### Integration tests

- New `tests/cli.rs` runs the real binary against an isolated temp `HOME`:
  scan → snapshot → report round-trip, `scan.max_depth` nested-repo discovery
  through `config set`, `snapshot migrate` on a legacy file, and `-f` rejection.

### CLI usage

- `projector rank`, `brief`, `activity`, `deps`, `orphans`, `search`, `size`,
  `inspect`, `stats`, `trend`, `report` all accept `-f <format>` with unified
  validation. No output values changed; only the error paths for invalid formats
  (and `stats`/`trend` no longer silently accepting garbage).
